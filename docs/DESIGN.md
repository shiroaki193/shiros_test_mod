# Mob Arms Race — 設計文件

> 苦力怕迫擊炮 vs. 村莊防空（雪傀儡近防炮、鐵傀儡擲貓、魔法黑貓）的軍備競賽 Mod。
>
> 已完成的功能和遊戲內用法請見 [FEATURES.md](FEATURES.md)。

- 目標平台：NeoForge 26.1.0.19-beta / Minecraft 26.1（ModDevGradle），與本機 PCL 的 `26.1-NeoForge_26.1.0.19-beta` 一致
- Mod ID：`mobarmsrace`，套件：`com.shiroaki193.mod`

### 實作時的設計決定

- **C1 用物品而不是騎乘**：26.1 原版禁止任何實體騎在玩家身上（`/ride` 也一樣），所以改成像「美西螈桶」那樣把整隻苦力怕存進物品。好處是玩家死亡、登出都不會出問題，也不需要自訂網路封包。
- **K1 不用騎乘抱貓**：生物身上有生物乘客時，原版會停用它 AI 的移動和看向控制，所以改成暫停貓的 AI 和重力，固定在鐵傀儡頭頂。若剛好在這時存檔，貓重新載入時會自動恢復。
- **C4 瞄準點而不是固定初速**：固定初速時，打遠距離要把視角抬高到看天空，落點圓圈就不在畫面上了。改成看著目標點，和迫擊炮苦力怕共用 60° 高拋求解。
- **雪傀儡散佈 18°**：實測攔截率（2 隻雪傀儡對 4 發齊射）：1.5° 到 14° 都是 100%，16° 為 96%，18° 為 90%，20° 為 67%。火力太密集，所以散佈要很大才會漏網；20° 以上會陡降。

## 開發與測試

所有工具和快取都在 workspace 內：`gradlew` 會把 `GRADLE_USER_HOME` 固定為 `.gradle-home/`（Gradle、JDK 25、Minecraft 檔案都放在那裡），VS Code 的設定也指向同一個位置。

| 指令 | 用途 |
|---|---|
| `gradlew test` | 彈道數學的單元測試，22 項（JUnit，[BallisticsTest](../src/test/java/com/shiroaki193/mod/ballistics/BallisticsTest.java)） |
| `gradlew runGameTestServer` | 在無畫面的伺服器上執行 14 項實機測試（[ModGameTests](../src/main/java/com/shiroaki193/mod/gametest/ModGameTests.java)），約 20 秒；全部通過時結束代碼為 0 |
| `MOBARMSRACE_MEASURE=1 gradlew runGameTestServer` | 額外執行雪傀儡散佈量測，在日誌輸出各散佈角度的攔截率（約 2 分鐘） |
| `python tools/setup_demo_world.py` → `gradlew runDemoClient` | 進入展示世界，每 20 秒輪流上演三個波次：雪傀儡攔截（夜間側視）、鐵傀儡擲貓（白天側視）、手持炮彈準星（白天第一人稱） |
| `gradlew build` | 產生 `build/libs/mobarmsrace-1.0.0.jar`，可放入正式遊戲的 mods 資料夾 |

- GameTest 場地是 [tools/gen_test_arena.py](../tools/gen_test_arena.py) 產生的 48×40×9 結構，射程約 40 格。120 格射程只在單元測試驗證，因為測試結構放不下。
- **每個 GameTest 都放在自己的環境（批次）裡依序執行**。原版會把同一批測試並排放置，間距只有 5 格，遠小於雪傀儡（48 格）和鐵傀儡（24 格）的偵測範圍；曾經發生鐵傀儡把貓丟向隔壁測試場地的苦力怕。
- 攔截帶有隨機性，所以「單發攔截」允許重試 3 次，「齊射防禦」允許重試 2 次，且只要求 4 發至少攔下 2 發。
- 展示世界的場景由 [tools/demo_datapack](../tools/demo_datapack/) 布置，只在開發環境使用。

## 核心概念

- **進攻方（苦力怕）**：把苦力怕變成拋物線遠程炮彈，逐步升級成迫擊炮、補給兵、可騎乘炮台。
- **防守方（村莊）**：雪傀儡負責末端攔截，鐵傀儡擲貓負責驅散，魔法黑貓負責強化攔截。
- 兩邊互相克制，而且攔截率不是 100%，偶爾要有炮彈突破防空，才有緊張感。

## 彈道規格

### 苦力怕炮彈

實作：[Ballistics.java](../src/main/java/com/shiroaki193/mod/ballistics/Ballistics.java)（遊戲內的 AI 瞄準、雪傀儡提前量都用它）；快速試算：[tools/ballistics_sim.py](../tools/ballistics_sim.py)

| 參數 | 數值 | 備註 |
|---|---|---|
| 重力 | 0.05 格/tick² | 和原版箭矢相同 |
| 阻力 | 0.99 /tick | 讓下降段比上升段陡，符合參考截圖；設成 1.0 弧線會左右對稱 |
| 發射仰角 | **固定 60°** | 不同距離的弧線形狀一致 |
| 初速 | 依距離求解，上限約 3.7 格/tick | 用模擬加二分搜尋，因為有阻力，沒有封閉解 |
| 最大射程 | **120 格** | |
| 物理順序 | 每 tick：垂直速度 −= 重力 → 速度 ×= 阻力 → 位置 += 速度 | 和 26.1 原版 `ThrowableProjectile#tick()` 相同，炮彈實體直接沿用原版物理 |

仰角固定 60° 時的模擬結果（目標與發射點同高）：

| 射程 | 初速 | 最高點 | 飛行時間 | 落地角 |
|---|---|---|---|---|
| 24 格 | 1.36 | 12 格 | 44 tick（2.2 秒） | 67° |
| 40 格 | 1.83 | 20 格 | 58 tick（2.9 秒） | 69° |
| 80 格 | 2.81 | 44 格 | 85 tick（4.2 秒） | 72° |
| 120 格 | 3.66 | 70 格 | 108 tick（5.4 秒） | 74° |

另一種做法是固定初速 3.5、求仰角（120 格時仰角 58°、最高點 65 格）。不過這樣近距離時仰角會接近 80°、最高點超過 80 格，看起來不自然，所以不採用。

**外觀**
- 尾跡：紅色 `DustParticleOptions`。每 tick 在上一個位置和目前位置之間補畫 6 到 8 顆，連成光帶，否則高速下會變成虛線。
- 齊射時每發落點偏移 ±1 到 2 格。

### 雪傀儡雪球

| 參數 | 數值 |
|---|---|
| 彈速 | 約 4 格/tick |
| 重力 | 無 |
| 射速 | 每 2 tick 一發 |
| 散佈 | 1.5°，漏網率靠散佈和開火距離自然產生 |
| 瞄準 | 用 C2 的彈道模擬推算提前量 |
| 開火條件 | 炮彈下降中、距離 28 格內、預測落點在雪傀儡 24 格內 |
| 命中判定 | 雪球與炮彈在前後各一 tick 內的最近接近距離 ≤ 1.1 格（避免高速穿透） |

實測：2 隻雪傀儡對 4 發齊射，連續 4 次測試都是 4/4 攔截。這比設計目標「偶爾有漏網」強，要調整的話可以在設定檔提高 `spreadDegrees`，或縮小 `engageRange`。

## 技術注意事項

- **區塊載入**：120 格大約是 7.5 個區塊。炮彈和目標所在的區塊必須在 entity-ticking 範圍內，也就是在玩家的模擬距離內，否則炮彈會停在半空中。
- **伺服器與客戶端**：彈道和命中判定都在伺服器端；落點準星在客戶端，用同一份彈道程式計算。
- **效能**：近防炮的雪球數量要設上限（例如每隻雪傀儡同時最多 N 顆），命中判定可以考慮用 raycast 取代大量實體碰撞。參考影片的彈幕有人反映卡頓。
- **爆炸破壞**：攔截爆炸只顯示效果、不破壞地形；落地爆炸是否破壞地形要跟隨 `mobGriefing` 遊戲規則。
- **平衡參數**：彈藥上限、攔截距離、射速、散佈、冷卻時間都放進設定檔。
